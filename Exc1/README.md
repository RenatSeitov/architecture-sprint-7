Для начала нужно распределить типы данных по категориям. Затем определить риски для каждой категории, объясню, почему они актуальны, и дам оценку для каждого риска.

## Типы данных по ISO/IEC 27001 и 27002:

``Публичные данные:`` Данные, доступные для всех, такие как маркетинговая информация или общедоступные отчёты.
``Внутренние данные:`` Информация, используемая внутри компании, например, документы сотрудников и внутренняя корреспонденция.
``Конфиденциальные данные:`` Клиентские данные, данные пользователей, информация CRM.
``Секретные данные:`` Критически важные данные, такие как учетные записи в Active Directory, пароли и финансовая информация.

## Риски и их категории:

## Для каждой категории данных выделим:
 - Утечку данных (например, из-за кибератак или человеческой ошибки).
 - Потерю данных (из-за сбоев системы или резервного копирования).
 - Искажение данных (в результате атак или ошибок при обработке).
 - Некачественные данные (в результате неправильного ввода или устаревания).
 - Обесценивание данных (из-за их компрометации или устаревания).

## Оценка рисков:

Я использую шкалу: незначительный, значительный, критический.

## Mindmap:

mindmap с центром «Безопасность данных» и разбивкой на категории данных, типы данных, риски, их оценки и объяснения.


```

* Безопасность данных
** Публичные данные
*** Маркетинговая информация
**** Риск: Утечка данных

****** Причина: Данные уже общедоступны, утечка не создаёт значительных проблем.
**** Риск: Обесценивание данных
***** Оценка: Незначительный
****** Причина: Данные могут устареть, но их ценность остаётся низкой.
** Внутренние данные
*** Документы сотрудников
**** Риск: Утечка данных
***** Оценка: Значительный
****** Причина: Утечка может нарушить конфиденциальность сотрудников.
**** Риск: Потеря данных
***** Оценка: Критический
****** Причина: Потеря данных может повлиять на процессы компании.
** Конфиденциальные данные
*** Клиентские данные
**** Риск: Утечка данных
***** Оценка: Критический

**** Риск: Утечка данных
```
